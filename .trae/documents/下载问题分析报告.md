# 下载问题详细分析与解决方案

## 🔍 问题现象

用户点击"下载"按钮后，视频文件没有在浏览器中下载，而是直接在新标签页中打开播放。

---

## 📊 原因分析

### 1. 浏览器对视频文件的默认行为

浏览器内置了视频播放器，对于以下 MIME 类型会倾向于"打开"而不是"下载"：
- `video/mp4`
- `video/webm`
- `video/ogg`
- `application/x-mpegurl` (m3u8)

### 2. 服务器响应头的影响

服务器返回的 `Content-Disposition` 头决定浏览器行为：

```
Content-Disposition: inline      → 在浏览器中打开（默认）
Content-Disposition: attachment  → 下载文件
```

**问题：** 我们无法控制远程视频服务器的响应头

### 3. 三种下载方案的对比

#### 方案 A：`<a>` 标签直接下载
```javascript
const a = document.createElement('a');
a.href = url;
a.download = 'file.mp4';
a.click();
```

**问题：**
- ❌ 对于跨域资源，`download` 属性被忽略
- ❌ 浏览器根据 MIME 类型决定是否打开
- ❌ 无法强制下载

#### 方案 B：Chrome Downloads API
```javascript
chrome.downloads.download({
  url: url,
  filename: 'file.mp4'
});
```

**优点：**
- ✅ 支持跨域资源
- ✅ 不依赖服务器响应头
- ✅ 直接保存到下载目录

**潜在问题：**
- ⚠️ 某些特殊 URL 可能受限（如 blob:、data:）
- ⚠️ 需要用户授权 downloads 权限
- ⚠️ 可能受浏览器安全策略影响

#### 方案 C：fetch + blob + objectURL
```javascript
const response = await fetch(url);
const blob = await response.blob();
const blobUrl = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = blobUrl;
a.download = 'file.mp4';
a.click();
```

**优点：**
- ✅ blob URL 是本地资源，强制下载
- ✅ 不受服务器响应头影响

**问题：**
- ❌ 受 CORS 跨域限制（需要服务器允许）
- ❌ 大文件会占用大量内存
- ❌ 可能丢失原始 Content-Type

## ✅ 最终解决方案

### 策略：分级降级

```
1. 优先使用 Chrome Downloads API（最可靠，支持跨域）
   ↓ 失败
2. 使用 fetch + blob（处理同源或 CORS 允许的资源）
   ↓ 失败
3. 显示错误提示，建议用户手动下载
```

### 实现代码

```javascript
downloadResource(url) {
  const fileName = this.getFileNameFromUrl(url);
  
  // 1. 优先尝试 Chrome Downloads API
  if (chrome.downloads) {
    chrome.downloads.download({
      url: url,
      filename: fileName,
      saveAs: false,
      conflictAction: 'overwrite'
    }, (downloadId) => {
      if (chrome.runtime.lastError) {
        // 2. API 失败，降级到 fetch
        this.downloadWithFetch(url, fileName);
      } else {
        this.showDownloadSuccess(fileName);
      }
    });
  } else {
    // 3. 没有 API，直接用 fetch
    this.downloadWithFetch(url, fileName);
  }
}
```

### 为什么这样设计？

1. **Chrome Downloads API 作为首选**
   - 扩展环境，有 downloads 权限
   - 不受 CORS 限制
   - 不占用内存
   - 直接保存到下载目录

2. **fetch + blob 作为备选**
   - 处理 API 无法处理的特殊 URL
   - 同源资源可以正常下载
   - 提供详细的错误信息

3. **详细的日志输出**
   - 方便调试和定位问题
   - 用户可以看到具体失败原因

## 🧪 测试场景

### 场景 1：同源视频资源
- **预期：** Downloads API 成功 或 fetch 成功
- **结果：** 文件下载到默认目录

### 场景 2：跨域视频资源（CORS 允许）
- **预期：** Downloads API 成功 或 fetch 成功
- **结果：** 文件下载到默认目录

### 场景 3：跨域视频资源（CORS 禁止）
- **预期：** Downloads API 成功，fetch 失败
- **结果：** 自动降级，最终通过 API 下载成功

### 场景 4：特殊 URL（如 blob:）
- **预期：** Downloads API 失败，fetch 可能成功
- **结果：** 降级到 fetch 下载

### 场景 5：超大文件（>500MB）
- **预期：** Downloads API 成功，fetch 可能内存不足
- **结果：** API 直接处理，不占用内存

## 📝 注意事项

1. **manifest.json 必须包含 downloads 权限**
```json
"permissions": ["downloads"]
```

2. **host_permissions 需要覆盖所有 URL**
```json
"host_permissions": ["<all_urls>"]
```

3. **用户可能需要授权下载权限**
   - 首次使用可能会弹出权限提示
   - 在扩展管理页面可以查看权限

4. **m3u8 文件特殊说明** ⚠️
   - **m3u8 是 HLS 流媒体的索引文件**，本身只有几 KB
   - 文件内容是视频分片（.ts）的播放列表
   - **下载后的 m3u8 文件需要专用工具处理**：
     - 播放器：VLC、PotPlayer 等可以播放 m3u8
     - 下载工具：N_m3u8DL-RE、FFmpeg 可以下载为 mp4
   - 下载 m3u8 时会弹出确认提示，告知用户文件性质
   - 如果需要下载完整视频，建议使用专门的 m3u8 下载工具

5. **为什么不用 fetch 下载大文件？**
   - fetch + blob 会将整个文件加载到内存
   - 大文件（>500MB）可能导致浏览器卡顿
   - Chrome Downloads API 使用流式传输，不占用内存

## 🔍 常见问题

### Q1: 为什么下载 m3u8 只有几百字节？
**A:** m3u8 本身就是索引文件，只包含视频分片的 URL 列表，不是真正的视频内容。

### Q2: 如何下载完整的 HLS 视频？
**A:** 使用专门工具：
- N_m3u8DL-RE（推荐）
- FFmpeg: `ffmpeg -i "url.m3u8" -c copy output.mp4`
- 一些在线工具或浏览器扩展

### Q3: 下载的视频无法播放？
**A:** 可能的原因：
- 文件未完整下载
- 视频加密（DRM 保护）
- 格式不支持（尝试 VLC 播放器）
